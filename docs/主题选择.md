# 主题选择与背景来源

本文记录截至 2026-11-12 的已实现规则；依赖边界以 [UI 架构](UI架构.md) 为准。

## 模式和选项

个性化设置中的「主题选择」卡片使用 `format_paint` 图标，右侧依次为「多主题」「单主题」「无主题」。内部模式仍编码为 `Independent`、`Merged`、`None`，兼容已有偏好记录。

- 多主题：显示「舞萌主题选择」「中二主题选择」两个触发框，各自选择对应音游主题或通用主题。
- 单主题：显示「主题选择」一个触发框，同一选择应用到两个音游。菜单顺序为通用主题、舞萌主题、中二主题。
- 无主题：隐藏主题触发框，在主题选择卡片下方显示「背景跟随配色」开关，两者组成同一组。沿用应用设置分组开关的 4dp 间距、相邻 4dp 小圆角和外侧 16dp 大圆角。两个音游共用种子色生成的 MD3 主副色，标题与常规内容用主色，两块标题三角分别用主、副色。保留三个主题 ID，切回其他模式可恢复。

无主题首版使用固定种子色 `#6750A4`，暂不提供 HSX 选色面板。独立算法依赖为 `com.materialkolor:material-color-utilities:2.0.0`，使用 `SchemeVibrant` 浅色方案与默认对比度；应用主色映射 MCU primary，装饰副色映射 tertiary。背景跟色默认关闭，使用 `#E6E6E6` 浅灰；开启后取种子色的 HCT 色相、彩度 16、明度 88，形成略暗、稍带灰感的浅彩色。前景容器保持纯白。背景开关直接刷新两页纯色 View，不重新加载背景或触发切换黑幕。

`ThemeOption` 区分已注册的 HTML 主题和通用主题。通用主题的稳定 ID 是 `placeholder`，展示名为「通用主题」，用原生 View 填充 `0x80000000`；它与灰色的无背景是两个来源。`BackgroundSelection` 为 `Html`、`Placeholder`、`None`，不把纯色伪装为 HTML 或新增音游类型。

每次打开菜单都从确认快照排除当前项。独立列表只允许所属音游主题；合并列表允许两种音游的主题。Registry 中额外登记的 15 个主题占位项用于验证长选单，复用所属音游现有 HTML 和不同配色；这些登记项是当前测试范围的一部分，不等于原生通用主题，也不代表新增了背景资源。

## 状态、事件与持久化

`GameSelectionController` 是稳定选择的唯一修改者。`GameSelectionState` 包含当前音游、舞萌主题 ID、中二主题 ID、模式、合并主题 ID。默认模式为独立背景；独立默认项为 Registry 的显式默认主题；默认合并项为通用主题。

`PersonalizationSettingsPage` 只缓存已确认的展示快照，不在点击时复制并修改选择；分段按钮、触发框也不乐观修改选中值。它们发送模式或选项意图，经 `SettingsAssembly` 交给 `MainShell`。主壳确认后更新设置页、背景来源、配色和偏好；事件被拒绝时仍以确认快照呈现。公开选择入口和背景翻页确认也同步该快照；设置页重建时读取当前快照。

持久化是 **兼容旧记录的 v1 字段扩展**，`GameSelectionFormat.VERSION` 保持 1，不执行版本号升级：

- `version`、`currentGame`、`maiThemeId`、`chuThemeId` 保留原有含义。
- 新增可选读取字段 `themeMode`、`mergedThemeId`。模式编码为 `independent`、`merged`、`none`；音游编码为 `mai`、`chu`，不保存 ordinal 或展示名。
- 无主题增加可选字段 `noneThemeSeedColor`、`noneThemeTintBackground`，仍使用 v1。种子色只接受不透明 ARGB；缺失或无效时逐来源回退到固定默认色。背景跟色缺失时默认关闭；原始颜色与开关保存进偏好和 Bundle，派生色板不落盘。
- 恢复按字段依次尝试保存状态、偏好、默认值；旧 v1 记录缺少新字段时，新字段从下一来源补齐，最终默认独立背景及通用合并项。原有有效音游和主题不丢弃。
- 未知版本整份来源不可用；未知或错属的单个 ID 仅使该字段继续回退，不反推当前音游。
- `UiPreferencesAdapter` 一次调用必填的完整字段写入接口；`SharedPreferencesUiPreferences` 使用同一个 Editor/apply 写入完整快照。读取记录允许为空，写入契约没有默认空实现。
- Bundle 编解码只搬运原始字段，恢复与校验规则集中在选择边界。以后若改变版本，必须先定义迁移，不能只增加 `VERSION` 导致旧来源被整体忽略。

## 触发框与分段按钮

`SettingsSegmentedChoice` 独立于卡片内其他选择组件。三个按钮按文字测量固定宽度，不随卡片等分拉伸；高度 26dp，文字上下左右使用同一数值的内边距。按钮间隔 4dp；选中为 13dp 胶囊圆角，未选中为 4dp 圆角。选择和取消都以 220ms 连续过渡形状与文字颜色，按压收缩及涟漪仍由 `PressSurface` 处理。

`LabeledDropdownField` 是自绘的 `PressSurface`，高度 44dp、基本圆角 22dp、描边宽度 2.5dp：

- 当前值与浮动标签的左侧位置均为 26dp；值最多一行并省略。
- 标签透明，不叠白色文字底块；描边 Path 在标签两侧真实断开，以圆形笔帽收尾。
- 白色填充内缩半个描边宽度，使白底和外部反馈的交界位于描边中心；不使用标签边缘模糊或渐变。
- 外环收缩终点使用实际白底边界，避免标签缺口处残留半个描边宽度的黑边后突然消失。
- 描边与反馈共用按压几何，避免出现两套固定外框。
- 透明度动画由触发框合成包含浮动标题及外环的完整绘制范围，避免默认 View 透明度层裁掉标题上半部；卡片伸缩仅额外裁剪内容底边。
- 箭头使用 `ic_chevron_right_24`，收起 90°、展开 270°，过渡 220ms。

背景切换开始时立即禁止主题按钮及触发框操作，文字、填充、描边和箭头的淡化程度跟随黑幕实际进度，黑幕撤下后恢复颜色，切换完成才解锁。禁用时收起面板，卸载时清除面板；窗口布局重建时重新按当前视口计算菜单预算。

模式切换保留两个触发框和背景开关实例，以同一个 300ms FastOutSlowIn 进度驱动内容高度、触发框与开关向上淡出／向下淡入及标题变化。无主题开关保留独立行的伸缩动画，组内间距同步展开；主题卡片底部与开关顶部的圆角随进度从 16dp 收至 4dp，开关收起后主题卡片恢复完整大圆角。多主题变单主题时，「舞萌」淡出，「主题选择」向左移动至原前缀起点，描边右侧缺口同步收窄；反向切换逆向呈现。位移按前缀实际文字宽度计算，当前值改变时独立淡出淡入。动画期间锁定控件，页面卸载时取消动画并收敛到已确认快照。

## 容器菜单与手势

`ThemeSelectorPanel` 将固定高度标题行、可展开描边和 `ThemeDropdownMenu` 组合在设置卡片内部，不创建 PopupWindow，也不占用独立焦点或全屏触摸遮挡层。标题行仍为 44dp，仅它负责开合与标题行按压反馈，选项分别处理自己的点击。展开先向下伸长描边，再将两侧描边断为上下两段，最后让菜单以 alpha 与 8dp 位移入场；收起反向。三者共用 `ThemePanelTransitionRunner` 的 420ms 非线性进度，连续开合从当前帧接续。菜单仍使用自己的 `MenuViewport`，没有阴影和滚动条。

默认标准行高 44dp、薄条高 6dp、各行间距 4dp、内边距 12dp。菜单直接接在标题行下面，以同一内边距控制左右及底部留白，不再叠加浮层锚点间隔。菜单预算按当前设置页视口计算，不依赖展开中的卡片高度，最多 6 个完整行；很矮的窗口同步缩小所有薄条和间距。除窗口不足的降级情况外，薄条彼此等高，所有间隔相同。

底部描边半径跟随末项实际绘制半径，额外加上菜单边界至描边中心的距离，使内外圆心重合；开合时在该半径与原胶囊半径之间连续过渡，兼容末项为薄条或完整卡片。标题白底随描边向下延伸，在外环之上遮住原胶囊的下半圈，内部涟漪和点击区域仍留在标题行；上方两段描边延长至标题外环峰值范围之外，避免断口与外环下缘相交；下方两段使用相同的直线长度，圆角继续独立跟随末项。

位置是高度、文字透明度和端点圆角的共同输入。每移动一个步长，只让一个完整容器收缩为薄条，同时让另一个薄条展开为完整容器；其他完整行和薄条保持高度，不让多条依次渐显。每组首项的上圆角（DMT）、末项的下圆角（DMB）随各自高度在 3dp 至 22dp 之间变化；其他角保持 4dp。通用主题自成一组，同时拥有 DMT/DMB；HTML 主题按所属音游分组，单主题菜单拼接后保留舞萌末项 DMB 和中二首项 DMT。端点在排除已选项后按实际相邻分组计算，新增注册主题无需修改索引或 ID；单项组同时拥有两个端点。首尾样式上下镜像，不把当前视口的任意一行重新当成分组端点。

- 慢拖跟手改变位置，抬手后也能吸附到完整选项边界，不依赖甩动。
- 快甩先惯性减速，再把剩余速度交给弹簧吸附；到边缘不硬切完成态。
- 弹簧和惯性互斥，同一位置只有一个动画执行者。再次按下先停止旧运动，再交给手指。
- 主指离开即终止本次手势，剩余指针的 MOVE/UP 被消费，不用无效指针读取另一根手指的速度；非主指离开不终止主指。
- 只有完整且静止的容器可选中；无障碍前后滚动同样按一个步长吸附。
- 多主题同时只展开一个面板，舞萌展开会推开中二框；个性化页统一合成模式动画高度与两面板的展开高度。切换另一个面板时关闭原面板。
- 外部点击、页面滚动和窗口失焦不作为关闭指令；菜单从 DOWN 起持有内部拖动手势，外部滚动仍归设置页。失焦停止运动并归位，不主动关闭面板。
- 系统返回优先收起面板；预测性返回的进度驱动描边、卡片高度、菜单透明度与箭头，取消后恢复展开和原翻页位置，确认后收起并释放菜单。
- 左上角返回直接回到设置父级，不先消费面板。页面卸载清除展开状态、翻页位置及待执行触觉；重新进入后面板收起，再次打开从起始位置显示。选择主题和主题切换禁用同样触发收起。

## 触觉

- 菜单完成入场后给一次轻微 `CLOCK_TICK`；相对标题行按下至少错开 120ms，任务至少延后 32ms，并检查交互许可、焦点及显示状态。预测性返回取消不重播入场触觉。
- 某个选项容器的实际绘制高度首次达到完整行高时，立即给一次 `CLOCK_TICK`。拖动、惯性和回弹都使用这一视觉条件，不等待弹簧彻底稳定。
- 初始已展开行不震；收缩至 90% 后才重新允许该项展开反馈，避免弹簧尾段重复震动。
- 不增加“抬手”或“回弹稳定后”的额外菜单震动。触发框关闭自身松手触觉，菜单项保留 `PressSurface` 原有按下和松手点击反馈。
- 关闭、重新触摸、失焦及卸载会取消待执行的打开触觉。

## 背景运行与切换

`BackgroundHost` 管理两个 `BackgroundPage`，页面缓存渲染入口，同入口不重复加载。纯色来源停止并隐藏 WebView，不发起 HTML 加载任务；宿主仍保留页内已创建的 WebView 对象，恢复 HTML 时复用。

`BackgroundSourceCoordinator` 只管理待加载来源和首帧缓存，不拥有当前音游选择。冷启动先加载当前页，该页首帧就绪后预加载另一页；用户提前切换时主动加载目标页的最新入口，不依赖旧页迟到回调。背景翻页确认保留真实 Pager settling，不调用再次定位的渲染入口。页内请求编号阻止失效视觉回调覆盖当前加载。

`BackgroundSwitchRunner` 保留当前固定黑幕时序：120ms 盖黑后更换来源，继续等待 260ms，再以 300ms 淡出；淡出开始 340ms 后收尾并恢复主题控件。主壳拥有选择和输入禁用状态，动画层只执行视觉时序，通过回调通知换源及完成。取消会移除延迟任务、取消属性动画并使旧回调失效。等待真实 HTML 首帧再撤黑幕的优化暂不处理。

## 文件职责

- `ui/theme`：纯主题描述、Registry、选项和背景来源模型，不依赖 View、Context 或存储。
- `ui/shell/selection`：纯选择快照、控制器、恢复与编解码；UI 偏好适配器是主壳使用基础存储的有限边界。
- `ui/settings`：组装与确认快照渲染，`ui/kit/settings`：触发框、分段按钮、菜单布局、手势和局部触觉。
- `ThemeMenuGeometry`：纯挤压几何及展开反馈门槛；`ThemeMenuGroups`：根据实际可选列表计算分组端点；均不提交选择、不启动动画。
- `ThemeCardTransitionRunner`：卡片高度、字段进退、标题及当前值过渡共享的帧状态与取消。
- `ui/animation/settings/ThemeMenuMotionRunner`：惯性与弹簧互斥、速度交接、停止和吸附收尾。
- `ThemePanelTransitionRunner` / `ThemePanelFrames`：面板统一开合进度与分阶段几何；`ThemeDropdownArrowRunner`：箭头动画及手势预览；`SettingsChoiceTransitionRunner`：分段按钮形状和文字动画。
- `ui/animation/shell/BackgroundSwitchRunner`：黑幕时序及取消，不提交主题状态。
- `ui/constants/dimensions/ThemeSelectionDimensions`、`ui/constants/motion/ThemeSelectionMotion` 和 `BackgroundSwitchMotion`：固定几何与运动参数。

动画只接收纯数据、View 或属性操作回调，不导入对应组件、设置页、主壳或存储实现。组件负责发意图和生命周期接线，动画负责自己的执行对象和取消。

## 验证范围

持续回归包括 Registry 和恢复规则、全部模式偏好完整读写、菜单逐项高度交换、完整高度触觉防重复，以及首帧迟到期间提前切页。真实 Android 触摸分发需补查慢拖、快甩、主指先离开、重新按下与取消；手机和平板均需检查窗口变化、菜单关闭、禁用状态及最终吸附位置。触觉的主观手感仍以设备体验为准。
