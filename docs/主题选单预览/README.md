# 主题选单预览：分步实现与验收

制定日期：2026-11-15。实现前基线：`58b1725`。

本文件是实现计划，不代表功能已经交付。实际完成情况、遥测样本与提交见 [验收记录](验收记录.md)。步骤必须按顺序闭环：实现本步 → 架构检查 → 手机和平板模拟器遥测 → 回归 → 更新记录 → 仅提交本步相关文件。失败先在本步修复，不带着未解释的回归进入下一步；每步独立本地提交，不 push。

每步同步修订已经改变的组件/架构契约，不等最后一步才让规范追上代码。凡新增时钟、加载任务或资源引用，当步即实现关闭、取消和卸载清理；第 5 步是专项验证与补漏，不是推迟生命周期正确性的理由。

## 1. 已确认的效果

### 1.1 完整展开的选项

- 保留左侧主题名称，去掉右侧可见单选圆圈；保留单选的无障碍语义、确认状态与点击当前项关闭菜单的行为。
- 最新修订：舞萌使用背景、人物两张静态 WebP，中二只使用背景。场景装饰直接烘入背景，不再有独立装饰层。背景左→右，人物右→左。
- 单项约 600ms 完成，之后保留静态结果，不循环播放，不维持空闲刷新。舞萌背景 0–300ms、人物 100–600ms；中二背景占满 600ms。
- 文字上方绘制，文字下方提供局部深色对比遮罩，向右渐隐；右侧人物不叠加此遮罩。它是按钮内部的图像遮罩，不是文字或组件投影，不使用 elevation、translationZ、setShadowLayer 或模糊阴影。
- 整个菜单打开时，完整行按从上到下的顺序错峰切入，初始间隔 35ms，各行动画重叠进行。开始时间以菜单实际开始显露为准，不在菜单尚不可见时提前播完。
- 当前选中项保留在原列表位置；完整展开时，整幅预览呈灰度效果，并叠加深灰半透明内描边，沿用选中胶囊的 G2 轮廓。选中状态仅由确认快照驱动。

### 1.2 折叠条带（2026-11-15 用户修订）

- 用户在实际查看后取消几何分割和错峰几何切入。折叠选项统一使用该主题完整展开时的低对比浅主题底色；不显示图片、几何分区或内描边。
- 展开/收缩仍消费现有行高，图片与浅底连续交接，快速反向从当前帧继续。
- Materkit 继续使用 shell 传入的实际主色计算浅底，并支持菜单打开期间更新。

### 1.3 衔接与底色

- 等待轮到切入的行，先显示由本主题主色向菜单底色混合得到的低对比浅底；不是所有主题统一显示灰色。选中项展开时使用其规定的灰色底。
- 展开时：图片随实际行高和局部呈现进度接替浅底；收缩时：当前预览连续淡出至浅底。不得先清空到白底、灰底或透明底再开始过渡。
- 快速反向拖动从当前帧继续，不重置成初始帧；行高始终来自现有 `ThemeMenuGeometry.expansion`，不得增加第二条行高动画。
- 不实现进程级“冷启动后只播一次”的记录。播放状态只属于当前菜单实例；关闭释放，重新打开按新一轮菜单显露处理。局部收缩/展开按本节规则衔接。

## 3. 架构与所有权

遵守 [UI架构](../UI架构.md) 和 [UI组件规范](../UI组件规范.md)。不做通用 DMI 重构，不建立 PreviewManager、全局缓存、播放记录服务或新的 Gradle 模块。

- `ui/theme`：主题主色与可选预览纯描述。预览仅包含资源路径及确实需要的裁切、锚点数据；各主题文件提供值，Registry 继续作为主题登记入口。这里不出现 Context、Bitmap、Drawable、View、解码器或加载回调。
- `ui/constants/dimensions`：内描边宽度、图层锚点的通用限制、位移上限等固定尺寸；`ui/constants/motion`：切入窗口、错峰间隔、重入门槛等固定时序。参数不散落到页面。
- `ui/kit/common/PressSurface`：提供通用的表面内容绘制槽。位置在填充之后、白色按压反馈和内部涟漪之前，使用该帧真实按压内缩与 G2 路径裁剪；外环仍按原顺序绘制。它不认识主题、展开程度或播放策略。
- `ui/kit/settings/SettingsButton`：继续拥有文字、单选语义和点击反馈。只增加必要的可选装饰/视觉配置，让主题菜单隐藏可见单选圆圈并设置文字呈现；其他标准按钮默认外观不变。菜单形状、灰度和内描边不与标准选择过渡争抢同一个属性。
- `ui/kit/settings/ThemeDropdownMenu`：拥有每行布局、共享折叠区几何、主题颜色的纯计算、资源请求及当前呈现数据。预览画面通过小型局部 Drawable/绘制实现接入。除每次菜单所需资源外不持有全局状态。
- `ui/animation/settings`：一个菜单局部执行器负责短时钟、逐行起点、各层进度、取消/反向/立即完成。输入是纯几何事实或回调，不导入具体菜单组件、shell 或主题状态控制器。已有滚动弹簧仍由 `ThemeMenuMotionRunner` 唯一执行；不能把其执行权移到预览动画。
- `ThemeSelectorPanel`：沿用现有打开、关闭、预测返回和卸载协议，转发预览显露/暂停/清理时机。菜单不得自行决定系统返回或设置导航。
- `settings`：只组合展示值和公开事件。`MainShell` 仍是稳定选择唯一所有者，不取得图片、菜单 View、滚动位置或每帧进度。

Materkit 的主色已由 shell 解析，接线时通过现有 settings → panel → menu 公开入口传入纯 `ThemeColors`，并支持颜色更新；不让组件去读取壁纸、偏好或导入 shell 实现。未选中的 Materkit 也要拿到其当前解析颜色。

允许按实际代码将纯几何、颜色和帧计算放入少量独立文件，便于必要测试；不把每一层图片拆成一套执行器，不为计划提前建立空类。

## 4. 生命周期、性能与视口

### 4.1 加载与刷新

- 在 UI 绘制之外按目标像素尺寸解码；`onDraw` 不解码、不做磁盘读取、不新建 Bitmap/Path/Paint/颜色矩阵。
- 只加载完整/正在交换的可见行及少量相邻候选。使用菜单局部、有明确字节预算的缓存；对 Bitmap 分配字节计数，避免按三张原始大图 × 全部主题常驻。
- 加载请求带菜单/尺寸代次，过期结果不能写回新菜单或旧布局；关闭、卸载时取消任务并释放引用。不可回收仍在 UI 绘制的共享 Bitmap。
- 图片未就绪时维持主题浅底，不闪白；同一行按完整可用画面交接，不允许各层异步到达时各自突然弹出。开发回退与素材缺失必须在记录中区分。
- 所有切入结束后停止时钟与主动 invalidation；保留最终静态图。没有拖动/按压/其他页面动画时，不得继续为预览驱动布局或刷新。
- 不增加现有菜单之外的输入等待；预览播放完成不是点击许可的条件。

### 4.2 中断与恢复

- 普通收起/页面卸载：取消预览时钟、延迟任务与加载回调；按现有面板退出流程释放菜单。
- 预测返回开始：冻结或接管局部播放，不以手势进度重新启动各层动画；取消返回恢复当前画面，确认返回走释放路径。
- 失焦/不可见：停止主动刷新，重新可见时按当前几何恢复或直接呈现目标，不能补播不可见时漏掉的一长串错峰。
- 系统动画关闭：立即应用完整目标，并执行同样的清理；不能只把 duration 设为零后遗漏完成回调。
- 连续拖动、惯性、回弹和反向时，以现有展开分数确定当前形态。使用局部状态防止边界抖动反复入队，不能复用会在 90% 反复重置的触觉门槛来决定整段入场。

### 4.3 手机、平板和窗口变化

- 全部几何读取当前菜单实测宽高和 density；不以手机/平板名称、屏幕分辨率或设备型号分支决定布局。
- 保留 44dp 完整行、最多 6 个展开槽位及现有薄条预算。高视口不把行或图片拉高填满空间；短视口继续使用现有压缩预算和滚动规则。
- 背景取景宽度 X = 实际行宽 W + 移动距离 D，D 沿用 56dp 上限。源图居中等比裁取 X/H 区域，初始右边缘与行右边缘对齐，向右移动 D 后左边缘与行左边缘对齐；全程覆盖，超出部分由表面剪裁。手机和平板共用素材，平板直接取中部。人物按行高和素材比例缩放并锚定右侧，保留文字区域；文字遮罩宽度依据实际文字范围并设上限，不随平板宽度无限扩散。
- 图层切入路程设上限，不要求人物从平板屏幕外侧飞越整行。共享几何使用统一实际坐标和稳定切线角度，不分别拉伸 X/Y 导致角度失真。
- 宽度、可用高度、density 或配置变化时重新计算预算、裁切和图像目标尺寸；取消旧尺寸代次。不能只在第一次 open 时测一次，也不能靠重新打开菜单才修正。

## 5. 分步交付

第 0–4 步为已完成的历史步骤，保留下述原始三层方案记录；当前效果以第 1–4 节最新用户修订为准，第 5 步同时完成两层/单层简化和背景重截。

### 第 0 步：文档和现有版本基线

交付本文件、验收记录和两个模拟器的现有菜单基线。此步不改变产品行为。

- 记录提交、APK SHA256、设备/AVD/API、分辨率、density、GPU、系统动画比例、背景来源及动画开关。
- 当前版本先构建、单测、lint，再跑主题菜单/选择语义/按压和设置组件相关设备回归。
- 实际页面采集菜单开合、滚动、稳定后的截图、gfxinfo framestats、内存与崩溃日志，明确样本时长和动作；后续复用相同协议。

提交：`docs(theme): 记录主题选单预览分步实现与验收基线`。

- 架构：检查 common 无主题运行依赖，所有形状使用实际 G2/按压路径；稳定选择仍从确认值渲染。
- 回归：浅/深/中性主色、上下两个折叠区、选中项在折叠区、独立/合并模式、点击当前项、单选无障碍、取消按压。纯色派生与共享几何只写有意义的边界测试。

- 遥测：两模拟器相同开合、滚动、空闲协议。

提交：`fix(theme): 将折叠预览改为浅主题色`。

### 第 5 步：视口变化与生命周期专项收口

前面每步已经做两种设备检查；此步补足平板横竖屏、窄分屏、宽而短/窄而高窗口及菜单开着时改变尺寸。核对高度预算重算、角度、锚点、位移上限和旧加载代次取消。接入完整预测返回取消/确认、失焦恢复、页面卸载清理。

- 回归：中途旋转/缩放、开合中返回、预测返回取消后反向拖动、加载中离开设置、动画关闭、背景确认更新和 Materkit 取色更新。
- 遥测：同一设备在记录过的窗口尺寸下比较；菜单关闭并等待后的内存需收敛，无持续预览回调或旧窗口绘制；截图核对安全区及当前窗口坐标。

提交：`fix(theme): 完善预览视口适配与生命周期清理`。如专项检查无须修复代码，只记录验收结果，不制造空的 fix 提交。

### 第 6 步：全量回归与最终验收

运行完整单测、lint、Debug 构建和两设备全部现有设备测试；真实页面复测主题模式、当前主题重选、长列表、普通返回、预测返回和设置导航。复核每步已同步的 UI 架构/组件规范与最终实现一致，删除阶段性错误描述。

- 与第 0 步使用同一基准设备、背景、GPU、窗口和动作；性能样本每种至少三轮，区分冷加载、暖加载、静止，不混合两设备数据。遥测时另一台模拟器不同时跑负载。
- 检查 CPU/UI/RenderThread、gfxinfo 帧分布、Bitmap/进程内存和关闭后的回调。图像与几何稳定后，预览不应再产生自身周期性刷新。
- 模拟器不能代替实体设备的触觉手感或最终视觉验收。不能仅以测试通过宣称稳定 60FPS，也不能用不同 GPU/背景的数字宣称性能改善。
- 出现可重复的性能退化，先通过单变量复测确认和修复，再提交该步；异常与未验收项明确留在记录中，不标记为完成。

提交：`test(theme): 完成菜单预览回归与验收记录`，有实际测试/文档变更时才提交。
