# 代理采集实测入口

## 一、链路作用

**实施状态（2026-11-17）：当前 Kotlin 项目的 debug 采集链路通过双设备实测。** 平板、手机各完成独立 10 轮舞萌六难度回归，均 10/10 成功；下文保留失败样本与未验证范围，不将调试通过标为正式传分功能完成。

先独立验证“微信授权 → 回调捕获 → NET 会话 → 原始页面落盘”。本轮不接查分器授权，不调用水鱼或落雪上传，也不生成本地成绩 JSON。测试可以由 ADB 启动，几 MB 的 HTML 逐块写入 App 私有目录，再通过 `run-as` 导出检查。

2026-11-17 在有线 OPPO Pad 上完成原版与新版对照。**舞萌已抓到有效成绩；中二返回业务错误 100106，用户确认尚未游玩新版本。** 中二不能算采集成功，需待账号满足 NET 登录条件后继续验证。

前期新版多轮返回 nginx 404。对照原版后，将授权 URL 获取推迟到微信实际打开本机入口时，并保持嵌套回调 URL 的原始编码；随后新版舞萌登录和下载通过。请求头、Cookie、TLS 及等待时序也做过对照，因此不能把全部历史失败唯一归因于其中一个改动。

## 二、架构规范

- `transfer/capture/NetCaptureProtocol`：校验回调目标、关联授权 state、转换回调协议。
- debug 源集的 `transfer/capture/LoopbackCaptureProxy`：本机入口、HTTP 回调识别和有限转发，不保存成绩，不负责平台上传。
- `transfer/net/GameNetClient`：本次任务独享 Cookie、重定向、请求和取消；网络访问绕过临时代理，保留证书验证。
- `transfer/net/NetPageInspection`：从有限页面前缀提取受控数字业务错误码，避免把 HTTP 200 错误页当作登录成功，不输出页面正文。
- `score/html/RawHtmlArchive`：负责逐页写入、大小上限、SHA-256、临时文件发布及失败清理，不持有全部页面的 String 缓存。
- debug 源集的 `transfer/test/CaptureTestService`：实验编排及 VPN 生命周期。`CaptureTestActivity` 只承接系统 VPN 授权、复制入口、打开微信和停止操作。

这是独立 debug 实验，不是正式功能的公开接口。Activity、服务及对应权限仅在 debug 清单注册。正式接入时按前七篇文档拆出任务入口和运行承载，页面不直接管理上述类。

参考架构与当前实现的区别：MaimaiData 和 Dart 都由完整 IP VPN/TCP 隧道捕获 HTTP 回调，再由 `CrawlerCaller` 等待、关闭 VPN、交给 `WechatCrawler` 登录和抓取。Dart 还把所有 HTML 留在静态 `htmlCache`，然后顺序上传。当前实验采用仅关联微信的 Android HTTP 代理建议，回调捕获只交付一次性地址，NET 客户端独立下载，每页立即写私有文件；不会把数 MB 正文留在 VPN 的全局 String 缓存中。正式 JSON 解析与平台上传应消费文件和元数据，继续作为后续独立环节。

原版对照采用空平台凭据，关闭真实上传。Dart 的业务/代理源码未修改：外置 instrumentation 驱动直接调用已安装原版的 Android 类，并在结束时把原有缓存写到私有目录。MaimaiData debug 版只增加绕过账号 UI 门槛及把上传出口改为本地保存，保留其代理、登录和下载实现；另有必要的构建兼容改动。

## 三、如何实现

先编译、安装 debug APK，确认有线设备序列号。交互测试脚本为 `tools/Invoke-NetCaptureTest.ps1`，例如：

```powershell
./tools/Invoke-NetCaptureTest.ps1 -Serial 8984e2ca -Game maimai -Difficulties '3' -OutputDirectory app/build/net-capture-export
```

脚本等待代理就绪。首次系统 VPN 弹窗必须先同意；服务建立 VPN 并发布 `WAITING_WECHAT` 后，Activity 才复制入口、跳转微信。复制操作会核对剪贴板内容。将其粘贴到文件传输助手，核对消息文字后发送并打开；不能用 ADB `input text` 代替粘贴，中文输入法可能改写 URL。

入口沿用参考项目的形态 `http://127.0.0.2:8284/<随机短码>`。这是设备自身的回环地址：本机 HTTP 服务在收到 GET 时才向华立申请新的微信授权 URL，并重定向微信 OAuth。参考项目还经过 `/auth?random=<时间戳>` 防缓存；本实验使用每次不同的路径和 `no-store`，HEAD 不生成授权。没有把授权码放进这条聊天消息。不要重新点击上轮消息或把 WebView 缓存的“回调已接收”当作本轮成功，必须核对当轮 `proxyEvents.callback` 和文件。

也可以直接用 ADB 启动。必须显式传 `start=true`，并创建新的 Activity 任务，避免恢复旧任务的 Intent：

```powershell
adb -s 8984e2ca shell am start -f 0x10008000 -W -n com.otokit.noharayh/.transfer.test.CaptureTestActivity --ez start true --es game chunithm --es difficulties 3 --ez openWechat true
```

同一时刻只运行一轮，开始下一轮前停止上一轮。停止及仅查看当前任务：

```powershell
adb -s 8984e2ca shell am start --activity-clear-top --activity-single-top -n com.otokit.noharayh/.transfer.test.CaptureTestActivity --ez stop true
adb -s 8984e2ca shell am start --activity-clear-top --activity-single-top -n com.otokit.noharayh/.transfer.test.CaptureTestActivity --ez start false
```

文件位于 `/data/user/0/com.otokit.noharayh/files/transfer-capture/<批次>/`，同目录含 `manifest.json`。根目录的 `status.json` 表示最近一次任务进度。预期成绩文件为 `player.html`、`recent.html`、`difficulty_<难度>.html`；`login_response.html` 只是登录响应诊断，可能是错误页，不能当成绩。

仅导出已有文件，不重新发起登录：

```powershell
./tools/Invoke-NetCaptureTest.ps1 -Serial 8984e2ca -ExportOnly -OutputDirectory app/build/net-capture-export
```

脚本通过二进制流导出 tar，避免 Windows PowerShell 文本重定向损坏文件。导出位置在被忽略的 `app/build/` 下。

连续稳定性回归使用 `tools/Invoke-NetCaptureReliabilityTest.ps1 -Serial 8984e2ca -Rounds 10`。逐轮交替冷启动与同进程重跑，舞萌固定六难度；每轮仍需在微信文件传输助手打开当轮剪贴板入口。收到有效回调后脚本切回测试 Activity，等待全部八页，再单独导出该批次，核对 SHA-256、字节数、HTML 结尾和各难度乐曲条目。结果保存在独立 `report.json`，失败不自动重试、不覆盖。本机授权码不跨轮复用，测试不会并发请求 NET，也不是服务器负载压测。

任务关联按批次目录识别，避免读取上一轮状态，也避免依赖 Windows/平板时钟完全同步。PowerShell 新版本可能自动把 JSON 时间转成 DateTime，不能先丢失时区再按本地时间解析。

## 四、需要注意的地方

- VPN 只关联 `com.tencent.mm`，没有默认 IP 路由，依赖微信遵守系统 HTTP 代理建议；当前设备有效，不代表所有微信版本、分身或 Android 系统均有效。实验要求 Android 10 及以上。
- 捕获到第一次有效回调后释放 VPN 和代理，再建立 NET 会话。取消、超时、撤销和异常也会清理；不修改全局系统代理，除非显式使用实验脚本的 `UseSystemProxy` 选项。该选项有恢复逻辑，本轮未使用。
- 默认采集单一 Master 难度。舞萌允许 `0,1,2,3,4,10`，中二允许 `0,1,2,3,4,5`。舞萌六个难度已实测。中二采用固定 GET 地址和前置表单 POST，不依赖图片链接；因业务登录条件不满足，前置表单及各难度页面仍未实机验证。
- 每页上限 32 MiB，缓冲写入 64 KiB，只保留最多 256 KiB 前缀做初步分类；完整页面仅在文件中。`SCORE_CANDIDATE` 是线索，`SAVED_FOR_INSPECTION` 也必须导出检查，不能直接认定有效成绩。
- 日志只记录受控阶段、错误类型和大小，不记录 HTML 正文、完整授权 URL、授权码或 Cookie。诊断 HTML 仍属于私有数据，不应提交到 Git 或公开分享。
- 当前网络兼容配置采用 OkHttp 4.10、旧桌面微信登录 UA、原版 Cookie 合并规则及旧 TLS 范围，证书验证保留；授权引导使用移动 UA。实验中回调后释放 VPN 并等待六秒，不是正式产品时序结论。不要把兼容测试配置当成最终网络架构规范。
- OPPO Pad 曾出现后台采集停顿，切回测试 Activity 后继续；对后续轮次在收到回调后返回 App。正式运行承载仍需单独验证后台、电量限制、取消、超时和进程恢复，不能直接宣称所有设备百分百成功。
- 当前项目已经包含采集核心和 debug ADB 入口；正式传分页、平台上传、自己的成绩 JSON、失败任务续跑与自动恢复尚未接入。上述 10 轮是单设备正常网络下的串行稳定性验证，不是并发负载测试，也没有完成真实弱网、断网、熄屏和长时间后台测试；本次未复现旧版偶发失败，不等于证明其所有根因均已消除。
- 本地 267 项单元测试通过；debug 构建和 Lint 已通过。相关用例覆盖回调目标/state、原始编码保留、按请求生成授权、重复交付、请求头分段、数 MB 文件完整性、中断写入清理和 HTTP 200 业务错误识别。新增 20 次代理启停及并发重复回调验证，另有 10 次写入断流后重新保存 2 MiB 文件验证；这两项是本地故障测试，不等于 30 次真实 NET 采集。NET 的真实结果以各批次文件为准。
- 参考源码位于 `D:/CodeProject/_参考/MaimaiData`，本轮检出的提交为 `9c52cfc`。参考其协议行为，不沿用完整 HTML 日志、全局缓存和隧道直接启动上传的组织方式。本组文档显式纳入版本管理，仓库 `docs/` 忽略规则仍保留。
