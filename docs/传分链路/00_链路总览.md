# 传分链路总览

## 一、链路作用

传分从用户在微信中授权访问舞萌或中二 NET 开始，由 OTOKiT 取得游戏会话、采集页面、保存原始 HTML，再上传到用户授权的查分器账号。以后可以把这些原始页面转换为 App 自用 JSON，用于用户成绩查询和展示。

这里存在两套独立授权：水鱼、落雪 OAuth 授予第三方平台的读写能力；微信／华立登录用于建立游戏 NET 会话。平台授权成功不代表游戏登录成功，游戏登录成功也不代表已经获准上传到平台。

本文档组始于 2026-11-15 的重构设计，2026-11-17 补充实施状态，遵守 [业务架构](../业务架构.md)。未标为已验证的目录及接口描述仍表示目标职责。旧 Flutter 仅作为协议行为参考，不要求保留其类名、全局变量或跨语言通信方式。

**当前进度（2026-11-17）：采集核心已实现，正式传分业务尚未完成。** 微信回调捕获、舞萌六难度采集和原始 HTML 调试存档已在平板与手机各通过 10 轮完整采集，共 160 份业务页面；证据与测试范围见 [代理采集实测](08_代理采集实测.md)。入口目前仅限 debug ADB 测试，原始文件尚未转换成 App 成绩 JSON，也未执行平台上传。

- 已实测：微信 VPN 授权后启动、回调关联与单次交付、舞萌玩家页/最近游玩/六难度下载、逐页私有落盘与文件完整性校验。
- 部分实现：测试服务的开始、停止、通知、超时及诊断状态；不代表正式任务生命周期和后台恢复已完成。
- 待验证：中二有效登录后的表单与成绩下载。当前账号未游玩新版本，返回业务错误 100106，已识别并保留证据。
- 待接入：查分器授权、平台上传/补传、本地 JSON、用户成绩、正式 UI、任务持久化与自动恢复；弱网、熄屏和长时间后台仍需专项验证。

## 二、架构规范

- `auth` 唯一管理两家查分器授权、账号身份和凭据生命周期。
- `transfer` 唯一管理传分任务，内部拆分捕获、NET 访问、上传、任务编排和 Android 运行承载。
- `score/html` 管理原始页面及采集批次，`score/json` 管理解析和本地用户成绩。
- `musicData` 提供曲目与谱面关联；不参与任务进度管理。
- `network / storage` 只提供基础能力；不拥有供应商策略、成绩覆盖规则或任务状态。
- 页面状态持有者只调用功能公开入口并观察状态，shell 不编排业务。

建议的内部位置为 `transfer/capture`、`transfer/net`、`transfer/upload`、`transfer/task`、`transfer/runtime`。它们是职责划分，不要求每个目录都建立 Repository、UseCase、接口和实现，也不要求拆成 Gradle 模块。

跨功能只交换所属功能的公开模型、结果或只读状态，不互相导入内部 DTO、数据库实体或文件布局。`score` 不反向调用 `transfer`，任务编排者接收保存和解析结果后自行决定下一步。

## 三、如何实现

按下列文档分别落实：

1. [查分器授权与回调](01_查分器授权与回调.md)：先验证水鱼回调可行性，管理授权与刷新。
2. [微信回调捕获](02_微信回调捕获.md)：临时建立捕获通道，取得一次性登录材料。
3. [NET 会话与页面采集](03_NET会话与页面采集.md)：完成游戏登录并按采集计划下载页面。
4. [原始 HTML 存档](04_原始HTML存档.md)：逐页可靠保存，为上传和后续解析提供来源。
5. [平台上传与补传](05_平台上传与补传.md)：分别执行两家平台适配并保存上传结果。
6. [本地 JSON 与用户成绩](06_本地JSON与用户成绩.md)：后续从存档转换，建立本地查询能力。
7. [任务生命周期与 UI 接入](07_任务生命周期与UI接入.md)：统一进度、取消、后台运行和恢复。

实施顺序：先完成授权回调可行性实验，再建立一条单游戏、单页面、单目标平台的完整流程，随后扩展难度、第二平台、中二和特殊谱面。第一阶段完成原始页面存档与上传即可，不以完整自用 JSON 为前置条件；账号识别、页面分类和有效性检查仍须第一阶段实现。

当前回调选择：优先实验本机 HTTP 回环方案；如果 Android 实测不可靠，暂缓该项，待 `otokit.cn` 配好 HTTPS 后验证 App Links。不把 `otokit.top` 作为新版依赖。不要将尚未通过验证的回调方案写成已完成能力。

## 四、需要注意的地方

- “HTTP”是传输协议，主要持久化对象是响应中的原始 HTML 和必要元数据，不是完整流量包或所有请求头。
- 把采集成功、本地保存成功、本地解析成功、平台上传成功分别记录；“流程走到末尾”不等于全部成功。
- 第一阶段验收应覆盖真实浏览器回跳、微信登录、至少一个有效页面保存和一个平台实际接收。编译成功不等于协议验证成功。
- 实现前复查供应商文档；接口、页面结构和 Android 后台限制会变化。与旧实现冲突时，根据现文档及实测确定，不为兼容旧代码保留无依据的补丁。
- 文档不会自动注册 OAuth 应用或修改网站。`docs/` 目录忽略规则保留，本组文档显式纳入 Git；其他新文档仍不会自动进入版本管理。
