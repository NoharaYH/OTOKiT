# NET 会话与页面采集

## 一、链路作用

**实施状态（2026-11-17）：舞萌 debug 实测通过，中二成绩待验证。** `GameNetClient` 已接入当前 Kotlin 项目，舞萌六难度在平板与手机各连续通过 10 轮；中二回调已捕获，但账号未游玩新版本，NET 返回 100106，尚未进入有效成绩采集。当前只保存待检查页面，正式账号身份识别、游戏适配器与任务接线仍需实施，详见 [实测记录](08_代理采集实测.md)。

使用捕获的登录材料完成华立到游戏 NET 的登录，取得当前用户的游戏会话，然后下载玩家资料、最近游玩和选定谱面的成绩页面。输出原始页面，不在这一层把成绩写入水鱼或落雪。

“模拟指纹”在实现中应具体化为经验证必要的 UA、请求头、Cookie、重定向和前置表单操作。不能把历史遗留请求头全部视为不可更改的协议要求。

## 二、架构规范

- 归 `transfer/net`，舞萌和中二各自维护页面路径与访问步骤，共用合理的会话和请求基础能力。
- 每趟任务独立拥有 CookieJar、登录状态和正在执行的请求。禁止全局静态 CookieJar、HTTP client 可变会话和当前游戏变量。
- 输入为一次性登录材料及不可变采集计划；输出为页面结果和必要的游戏账号身份。页面保存由编排者调用 `score` 完成。
- `network` 可以提供客户端构造、超时等基础能力，不拥有游戏页面规则。游戏会话与查分器请求使用隔离的凭据范围，防止 Cookie 或 Authorization 错发到其他域名。

## 三、如何实现

### 1. 建立会话

处理授权回调并遵循已验证的跳转链；逐步校验允许的目的域名，不在跨域跳转时无条件转发敏感请求头。登录结束后访问玩家信息页，确认游戏、账号身份及页面有效性，再进行成绩采集。

游戏账号尚未识别的页面只能保存在待确认批次中，不能合入其他账号成绩，也不能直接当作目标账号数据上传。账号识别失败应给出独立错误。

### 2. 构造页面计划

计划使用语义类型区分玩家资料、最近游玩、普通难度、宴谱和 WORLD'S END，避免把 `-1/-2/10` 散布在整个业务中。需要接口数字时在游戏适配器内部转换。

舞萌旧实现的路径参考：

- 玩家资料：`friend/userFriendCode/`。
- 最近游玩：`record/`。
- 普通难度：`record/musicSort/search/?search=V&sort=1&playCheck=on&diff={difficulty}`。
- 宴谱：`record/musicGenre/search/?genre=99&diff=10`。

中二旧实现的路径参考：玩家资料 `home/playerData/`，最近游玩 `record/playlog/`，普通难度 `record/musicGenre/` 下的具体页面，WORLD'S END 为 `record/worldsEndList/`。普通难度可能需要先向 `sendBasic` 等路径 POST，再 GET；表单 token 应按实际页面／Cookie 协议取得，不能继续默认“第一个 Cookie 就是 token”。

这些路径在实现前通过真实页面和现文档核对，版本变动封装在游戏适配器中。

### 3. 下载与交付

第一版同一 NET 会话串行采集，显式控制访问间隔。每页检查 HTTP 状态、实际跳转位置、内容类型及页面特征，区分登录页、维护页、错误页、有效空成绩和有效成绩。

有效页面立即交给编排者保存，不等全部页面齐全后才保存。网络故障可有限重试；登录失效停止依赖该会话的采集，避免连续抓取登录页面。取消时取消当前请求和后续等待。

## 四、需要注意的地方

- HTTP 200 不能证明拿到了成绩；解析到零条也不能证明用户没有成绩。
- 旧版采集了最近游玩却在上传循环跳过。新版必须明确最近游玩的用途和目标平台支持情况，不继续无用途下载或默默丢弃。
- 原始页面可能包含账户信息或隐藏表单字段，按私有用户数据保存，不直接输出到日志。不要为了排障打印整份 HTML。
- 优先使用现代 TLS 默认配置，保留证书验证；旧 TLS 配置与桌面微信 UA 只有得到当前证据支持才保留。
- 验收覆盖舞萌／中二、空成绩、特殊谱面、会话过期、维护页面、缺页及取消。脱敏 HTML 样本用于回归，在线实测用于确认请求流程。
- 参考：[落雪舞萌支持页面](https://maimai.lxns.net/docs/api/maimai)、[落雪中二支持页面](https://maimai.lxns.net/docs/api/chunithm)；页面上传支持不等于 NET 登录协议保证。
