# 任务生命周期与 UI 接入

## 一、链路作用

**实施状态（2026-11-17）：仅调试承载部分实现。** `CaptureTestActivity/Service` 支持 ADB 开始/停止、首次 VPN 授权、阶段观察、前台通知、超时和资源释放；两设备连续回归均在回调后返回测试页。正式任务协调器、传分页、持久化恢复、失败任务续跑，以及弱网/熄屏/长期后台验收均未完成。

把授权检查、微信捕获、NET 采集、本地保存和平台上传组织成一趟可观察、可取消、可恢复部分工作的任务。用户切换页面、切换当前游戏或把 App 放到后台时，仍能知道实际进度和结果。

任务不是 VPN 的同义词：VPN 仅用于捕获阶段，释放 VPN 后采集和上传还可能继续。

## 二、架构规范

- `transfer/task` 是任务状态的唯一修改者；各执行器返回结果或事件，不共同修改一组全局布尔值。
- `transfer/runtime` 提供 Android 服务承载与通知，把系统停止事件交给任务协调器；服务实例和 Activity 不成为第二份业务状态源。
- 公开操作至少覆盖开始、取消、查询／观察和重试失败上传。名称由实现确定，不预先扩展成万能工作流框架。
- 输入固定游戏、采集范围、上传目标及账号身份。第一版只允许一趟活动采集或执行任务，重复开始返回已有任务或明确拒绝，不覆盖旧任务。
- UI 状态持有者订阅公开状态并映射成文案；界面选择只影响下一次开始。shell、kit、chrome 不直接访问任务执行器。

## 三、如何实现

### 1. 任务状态

顶层阶段区分准备、等待微信授权、建立 NET 会话、采集保存、上传及终态。页面数量可以确定时提供已完成／总数；等待用户操作时显示阶段，不伪造百分比。

页面子结果记录采集与保存；目标平台子结果记录未开始、进行中、成功无变化、成功有变化、失败、结果不确定、取消或不支持。终态依据本次请求的范围汇总为成功、部分成功、失败、取消或中断，不能由最后一条日志决定。

第一阶段自用 JSON 尚未实现，不把它纳入传分成功条件；以后启用解析时，仍独立展示本地解析结果。

### 2. 后台运行与取消

使用明确的任务作用域管理协程和请求，不创建无人持有的临时 CoroutineScope。任务需要后台继续时，由符合当前 Android 限制的前台服务承接，具体服务类型、权限和启动时机在实现前按目标 SDK 核实；不能假设退出 Activity 后普通协程会可靠运行。

捕获结束即可释放 VPN，后续任务保持自己的运行承载。取消向下传递到监听器、HTTP Call、等待和上传队列，清理操作可重复执行。对已经发生的远端提交不作撤销承诺。

### 3. 持久化与恢复

持久化任务输入快照、任务 ID、阶段、批次与页面引用、每个平台账号标识和上传结果。不保存登录回调、Cookie 或令牌副本。

进程重启后，把遗留运行态标记为中断并核对存档。可以让用户继续上传已保存页面；没有可用 NET 会话时需要重新微信登录，不自动重放旧回调，也不将旧任务继续伪装为原会话。

若平台上传结果未知，恢复界面明确提示，并按该端点的重复提交语义决定是否重试。若原授权账号已变化则等待恢复原授权或明确建立新的上传操作。

### 4. UI 与日志

页面可观察本次任务和最近结果，显示阶段、页面进度、两家平台独立结果及取消／重试入口。Activity 重建重新订阅同一任务，不能重新触发 start。

日志由结构化事件生成，包含任务关联、阶段、页面类型和脱敏错误分类。禁止 `[HTML_DATA_SYNC]` 式携带 HTML 和 Token 的日志协议；业务正确性不依赖日志订阅者是否存在。

## 四、需要注意的地方

- “后台继续”不保证进程永远存活；必须同时设计可中断、可恢复的结果。
- 手机锁屏、切换游戏、旋转、页面重建、服务撤销及进程被杀都应纳入验收，不能只测前台一次成功。
- 只读状态不得暴露可变内部集合，防止 UI 间接修改任务事实。
- 第一版保持单任务和串行 NET 采集即可，不预先实现多账号并发队列、常驻自动同步或复杂定时调度。
- 验收重点是取消真的停止后续请求、重复开始不会双跑、部分成功可准确解释、重启后不会重放登录，以及补传不会串到另一个平台账号。
